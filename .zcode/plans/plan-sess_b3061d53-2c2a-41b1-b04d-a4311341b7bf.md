# Сущности в зрении + типы блоков в лучах + DQfD

Все три улучшения из обсуждения. Меняют наблюдение (старые data/*.pt и записи станут несовместимы — авто-детект уже есть, записи надо будет перезаписать).

## 1. Сущности в состоянии (зрение на мобов/игроков/предметы)

**js/entities.js (новый):** собирает из `bot.entities` ближайшие сущности (радиус `entities.radius`, по умолчанию 16) до `entities.max_tracked` (8) штук. Для каждой: позиция в **локальной системе взгляда** наблюдателя (forward/right/up, нормировано на радиус), дистанция, класс (0=враждебная, 1=пассивная, 2=игрок, 3=предмет), стабильный `id`. Враждебность — по списку имён мобов (zombie, skeleton, creeper, spider, enderman, witch, ...). Фиксированная длина списка с паддингом — формы тензоров стабильны.

- **js/state.js:** поле `entities` в состоянии; для record.js — сущности из мира обсёрвера, но в системе координат игрока (ограничение: сервер шлёт сущности только вокруг самого обсёрвера — задокументировать).
- **py/state_encoder.py:** сущности → вектор `9 * max_tracked` (present, forward, right, up, dist, one-hot класса). Обновить `scalar_dim()`.
- **gathering.py:** награда за убийство: моб был в prev-состоянии близко (<4 блоков) и исчез в curr → +kill_reward. Уточнённый штраф: `attack_center` в пустоту = нет ни блока, ни сущности в конусе.
- **looking.py:** без изменений (работает с целью).

## 2. Класс блока в каждом луче зрения

- **js/vision.js:** `blockClassId(name)` → 0..K-1 (K=10: небо/воздух, древесина, камень, земля/песок, растения, жидкость, руда, снег/лёд, стекло, прочее) — та же философия, что у палитры цветов. Ячейка становится `[r,g,b,d,t]` (5 значений), t — целочисленный класс.
- **py/state_encoder.py:** t one-hot'ится на стороне Python → каналов на кадр `4 + K`; `vision_channels() = (4+K)*frame_stack`. Семантика классов нужна только Node, Python работает с голыми id — контракт это целое число, число классов K в config.
- Настройка: `vision.block_classes: 10` в config.json + DEFAULTS в js/config.js и py/config.py.

## 3. DQfD — демо-переходы в replay buffer

- **py/replay_buffer.py:** отдельный `demo` deque (не вытесняется) + смешанное сэмплирование: доля `train.demo_fraction` (0.25) батча из демо, остальное из живого опыта; `sample()` возвращает дополнительно маску `is_demo` и экспертное действие.
- **py/demo_loader.py (новый):** читает `data/demonstrations.jsonl`, прогоняет состояния через FrameStacker (как train_bc) и **через свежий экземпляр активного модуля** — on_tick + compute_reward на записанных состояниях дают демо-переходам честные награды именно этого модуля. done по разрывам тиков.
- **py/dqn.py:** к loss добавляется margin-loss для демо-строк (DQfD): `max(0, Q(s,a_expert) − max_{a≠expert} Q(s,a) + margin)`, margin в конфиге (`train.demo_margin`, 0.5... награды у нас до ±100, возьму 1.0).
- **py/ai_loop.py:** после инициализации агента — загрузка демо в буфер (флаг `train.demo_preload: true`). Обернуть `load_bc` в try/except как у чекпоинтов (старые bc_weights после смены наблюдения вызовут RuntimeError).
- **py/train_bc.py:** без изменений кода, но старые записи упадут с понятной ошибкой — добавить дружелюбное сообщение «перезапиши демо».
